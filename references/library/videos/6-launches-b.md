**Lessons for her launch films:**
1. Frame 0 should be the subject or the problem, never a logo sting (the handbook visible in #19 says the same). If you open on the brand, keep it to 1s and make it native: a terminal or connector screen, like #26's game menu.
2. Show the install literally and early: paste the MCP URL into a connector field, or ⌘V a docs URL into a coding agent, then show "Working for…", the diff, and the live result (#8, #14). Rebuild those panels in vector, big and crisp.
3. Run one scenario end to end in ~6-8s, with a number in the accent colour: question → answer with the number → consent click → "Done" (#5, #6).
4. Prove breadth by scrolling the real list (skills, integrations, platforms) or with one labelled shot per capability (#8, #14, #26), not with a stated count.
5. Keep 70-80% of frames moving and stills under ~2s, but don't chase cut rate. Let the camera, cursor and UI morphs carry the motion (the top 8 have a median of 2.3 cuts/min), and save flicker cutting for a 2-4s opener (#13).
6. For memory-graph shots: zoom out from one labelled memory to the whole graph in under 2s (#4), drag a node to show its edges, dive in until the titles read, then resolve a path into a readable strip (#17) or a source panel (#18).
7. Give the film a through-line: a running counter (#9's "SPENT $"), a persistent "receipt" inset (#3), or a callback character who returns before the lockup (#14).
8. End on the URL or install command on its own card, then hold the lockup for 3-5s (#1, #6, #9, #14). For capture-style clips, loop back to the first frame instead (#17).
